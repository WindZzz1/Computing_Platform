# 安全政策

## 漏洞报告

如果您发现安全漏洞，请不要创建公开 issue。相反，请发送邮件到 [项目邮箱]。

在邮件中请包含：
- 漏洞描述
- 受影响的版本
- 复现步骤
- 可能的影响
- 建议的修复方案

## 支持的版本

当前支持以下版本的错误修复和安全更新：

| 版本 | 支持状态 |
| --- | --- |
| 1.0.x | ✅ 支持 |
| 0.9.x | ⚠️ 仅安全更新 |

## 安全最佳实践

### 依赖管理
- 使用 Dependabot 自动更新依赖
- 定期审查和更新依赖库
- 及时处理已知的安全漏洞

### 访问控制
- 使用 JWT 进行身份验证
- 实施基于角色的访问控制（RBAC）
- 定期审查用户权限

### 数据保护
- 敏感数据加密存储
- 使用 HTTPS 传输数据
- 定期备份数据库

### 代码安全
- 使用静态代码分析工具
- 实施 code review 流程
- 定期进行安全审计

## 披露政策

我们承诺在 48 小时内确认收到的安全报告，并在 7 个工作日内提供初步评估。

严重漏洞将在确认后尽快发布修复版本。修复版本的发布时间表取决于漏洞的严重程度：

- 🔴 严重：48小时内发布修复
- 🟡 高优先级：7天内发布修复  
- 🟢 中优先级：30天内发布修复
