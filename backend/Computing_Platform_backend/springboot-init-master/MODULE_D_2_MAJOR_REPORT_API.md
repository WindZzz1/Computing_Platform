# 模块D-2：专业级报告与穿透式台账 API 文档

## 功能概述

当前后端已经提供专业报告模块的控制器入口和权限框架，但报表服务本身仍未完整实现。

也就是说:

- 接口路径已经固定
- 角色校验已经接入
- Token 登录访问链路已经补通
- 雷达图数据、穿透式台账数据、Excel 导出仍会返回“待完整实现”

## 当前已开放接口

### 1. 获取专业达成度雷达图数据

- 接口地址: `POST /major-report/radar-data`
- 权限要求: `ROLE_LEADER` 或 `ROLE_EDU`

请求参数:

```json
{
  "majorId": 1,
  "termId": 1,
  "grade": "2021"
}
```

当前行为:
- 校验 `majorId`、`termId`、`grade`
- 读取当前登录用户 ID 和角色
- 调用 `validateMajorPermission(...)`
- 进入服务层 `getRadarChartData(...)`

当前真实状态:
- 服务层当前直接抛出 `雷达图功能待完整实现`

## 当前认证与权限行为

### 登录态来源

当前控制器已兼容:

- JWT 拦截器写入的 `request.attribute("currentUser")`
- 老 session 中的 `userId`、`userRole`

这意味着:
- Token 登录访问本模块已经可以正确识别用户
- session 登录方式也仍可用

### 当前业务权限规则

服务层当前实现:

- `ROLE_EDU` 返回 `true`
- `ROLE_LEADER` 返回 `true`
- 其他角色返回 `false`

说明:
- 当前并没有按“负责人只可看自己专业”做精细限制
- 目前属于角色级放行，不是专业归属级放行

## 当前错误返回

### 参数错误

```json
{
  "code": 400,
  "message": "专业ID、学年学期ID和年级不能为空"
}
```

### 权限不足

```json
{
  "code": 403,
  "message": "无权访问该专业数据"
}
```

### 功能未完成

```json
{
  "code": 500,
  "message": "获取雷达图数据失败: 雷达图功能待完整实现"
}
```

或

```json
{
  "code": 500,
  "message": "获取穿透式台账失败: 穿透式台账功能待完整实现"
}
```

## 与旧文档的差异说明

以下内容在旧版说明里写得比较完整，但当前代码还没有真正落地:
