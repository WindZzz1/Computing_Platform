# 前端角色权限说明

本文档整理当前前端按角色开放的页面入口、默认首页和联调注意事项。后续如果 `src/utils/roleAccess.ts` 或后端权限规则调整，需要同步更新本文档。

## 1. 角色列表

当前前端识别四类角色：

| 角色编码 | 角色名称 | 主要职责 |
| --- | --- | --- |
| `admin` | 系统管理员 | 维护学院、专业、学年学期、用户等系统字典和账号 |
| `edu` | 教务管理员 | 维护课程、学生、教学班、成绩导入，并推进课程级/专业级计算 |
| `leader` | 专业负责人 | 维护毕业要求、指标点、矩阵配置，查看专业级计算和报表 |
| `teacher` | 课程教师 | 维护课程大纲、课程目标、考核点，录入成绩并查看课程报表 |

## 2. 默认首页

登录成功后，前端会根据角色跳转到不同默认页面：

| 角色 | 默认页面 |
| --- | --- |
| `admin` | `/basic-data` |
| `edu` | `/basic-data` |
| `leader` | `/dashboard` |
| `teacher` | `/syllabus` |

如果用户访问无权限页面，路由守卫会跳回该角色的默认页面。

## 3. 页面访问对照

前端侧页面入口由 `src/utils/roleAccess.ts` 维护。

| 功能模块 | 页面 | admin | edu | leader | teacher |
| --- | --- | --- | --- | --- | --- |
| 首页 | `/dashboard` | 否 | 否 | 是 | 否 |
| 基础数据管理 | `/basic-data` | 是 | 是 | 是 | 否 |
| 课程库 | 基础数据内部模块 | 是 | 是 | 否 | 否 |
| 毕业要求与指标点 | 基础数据内部模块 | 是 | 否 | 是 | 否 |
| 矩阵配置 | `/matrix` | 否 | 否 | 是 | 否 |
| 课程大纲管理 | `/syllabus` | 否 | 否 | 否 | 是 |
| 成绩管理与计算准备 | `/score` | 否 | 是 | 否 | 是 |
| 计算中心 | `/calculation` | 否 | 是 | 是 | 是 |
| 报表中心 | `/report` | 否 | 是 | 是 | 是 |

说明：

- “页面访问”表示前端菜单和路由是否开放。
- 某些页面内部还会根据角色显示不同区域，例如基础数据管理中 admin 更偏字典和用户，edu 更偏课程和学生，leader 更偏毕业要求和指标点。
- 页面开放不等于所有接口都能调用，后端仍可能按角色做更细粒度鉴权。

## 4. 页面内部权限补充

### 基础数据管理

- `admin`：学院、专业、学年学期、用户管理。
- `edu`：课程库、学生库、教学班相关基础数据。
- `leader`：毕业要求、指标点维护。

### 成绩管理

- `edu`：教学班、学生库、教学班学生绑定、成绩导入准备。
- `teacher`：查看本人教学班，录入或维护课程成绩。

### 计算中心

- `teacher`：课程级计算相关能力。
- `edu` / `leader`：专业级计算查询与执行。
- `admin`：部分页面内部逻辑会支持数据查看或管理，但当前左侧入口主要按 `edu`、`leader`、`teacher` 开放。

### 报表中心

- `teacher`：课程报表、学生原始成绩明细。
- `leader` / `edu`：专业级报表、指标点达成度结果。
- `admin`：部分台账或矩阵导出能力在页面内部保留，但当前主入口以业务角色为主。

## 5. 常见权限问题

### 登录后看不到某个菜单

先确认当前账号角色是否应该拥有该功能。前端菜单是按角色过滤的，不同角色看到的左侧导航不同。

### 访问页面后被跳转

路由守卫会检查页面对应功能是否允许当前角色访问。如果不允许，会跳到当前角色默认首页。

### 接口返回未登录

常见业务码：

```text
40100
```

处理方式：

- 退出后重新登录。
- 检查浏览器 `localStorage.token` 是否存在。
- 在 Network 中确认请求头是否带有 `Authorization: Bearer <token>`。

### 接口返回无权限

常见情况：

```text
40101 / 403 / 当前角色无权限
```

这通常不是前端接口路径写错，而是当前角色不能访问该后端接口。处理时应先换对应角色账号测试，再判断是否需要后端调整权限。

## 6. 联调建议

- 测试字典、用户和学年学期时，优先使用 `admin`。
- 测试课程库、学生库、教学班和成绩导入时，优先使用 `edu`。
- 测试毕业要求、指标点、矩阵和专业级结果时，优先使用 `leader`。
- 测试课程大纲、考核点、课程级计算和课程报表时，优先使用 `teacher`。

一句话总结：

```text
如果页面没有入口，先看前端角色权限；如果页面有入口但接口失败，再看后端接口权限和登录 token。
```
