# 前端演示流程：从基础数据到专业级达成度

本文档用于课堂汇报、项目验收和新成员交接，说明前端如何按 OBE 业务流程完成一次完整演示。演示重点不是逐个展示页面，而是讲清楚数据如何从基础配置流转到课程级、专业级达成度结果。

## 1. 演示目标

通过一次完整演示说明：

- 基础数据如何为后续计算提供统一数据源。
- 毕业要求、指标点、课程目标和考核点之间如何建立关系。
- 学生成绩如何汇总为课程目标达成度和课程级达成度。
- 多门课程的课程级结果如何支撑专业级达成度。
- 报表页面如何用于展示、复核和导出结果。

## 2. 推荐演示账号

不同页面按角色开放，演示时建议准备多个账号。

| 演示阶段 | 推荐角色 | 说明 |
| --- | --- | --- |
| 基础字典、课程库 | `admin` / `edu` | 维护学院、专业、学年学期、课程和教学班 |
| 毕业要求、指标点、矩阵 | `leader` | 配置专业认证中的毕业要求和课程支撑关系 |
| 课程大纲、成绩录入 | `teacher` | 配置课程目标、考核点并导入成绩 |
| 专业级计算、报表查看 | `edu` / `leader` | 汇总课程级结果，查看专业级达成度 |

如果登录后看不到某个菜单，优先检查当前账号角色是否匹配。

## 3. 完整演示路线

### 第一步：基础数据管理

页面入口：`/basic-data`

演示内容：

- 学院字典：说明系统先统一学院来源。
- 专业字典：说明后续课程库、教学班和专业级计算都需要绑定专业。
- 学年学期：说明系统按学年学期组织课程、成绩和计算结果。
- 课程库：展示课程代码、课程名称、学分、课程性质、所属专业、所属学院等信息。
- 教学班与学生名单：说明课程计算需要明确“哪门课、哪个班、哪些学生”。
- 毕业要求与指标点：说明专业认证的最终评价对象是毕业要求和二级指标点。

演示重点：

```text
基础数据是整个平台的底座。后续矩阵、成绩导入、课程级计算和专业级计算都依赖这里的数据。
```

常见问题：

- 课程库没有数据时，后续课程大纲和成绩导入无法选择课程。
- 专业或学年学期缺失时，专业级计算筛选条件不完整。
- 毕业要求和指标点缺失时，矩阵配置和专业级结果无法形成完整闭环。

### 第二步：矩阵配置

页面入口：`/matrix`

演示内容：

- 展示课程对毕业要求指标点的支撑关系。
- 说明矩阵中的权重表示某门课程对某个指标点的贡献程度。
- 重点展示列合计校验，解释每个指标点的课程支撑权重需要满足系统规则。

演示重点：

```text
矩阵配置回答的是“哪些课程支撑哪些指标点，以及支撑比例是多少”。
```

建议讲法：

- 横向看：一门课程可能支撑多个指标点。
- 纵向看：一个指标点通常由多门课程共同支撑。
- 专业级达成度计算时，会用这些权重汇总课程级结果。

### 第三步：课程大纲管理

页面入口：`/syllabus`

演示内容：

- 选择课程，展示课程目标列表，例如 CO1、CO2、CO3。
- 配置课程目标对指标点的内部贡献权重。
- 维护考核点，例如期末考试、平时作业、实验报告。
- 说明考核点需要绑定课程目标，才能把成绩映射到课程目标达成度。

演示重点：

```text
课程大纲管理回答的是“这门课内部如何评价学生是否达成课程目标”。
```

概念关系：

```text
考核点 -> 课程目标 -> 指标点 -> 毕业要求
```

常见问题：

- 课程目标没有配置权重时，课程级计算缺少依据。
- 考核点没有绑定课程目标时，成绩无法归入对应课程目标。
- 内部贡献权重校验不通过时，建议先修正权重再演示计算。

### 第四步：成绩管理与课程级计算

页面入口：`/score`

演示内容：

- 选择教学班和课程。
- 下载或说明成绩导入模板。
- 导入学生成绩文件。
- 预览原始成绩和导入结果。
- 触发课程级计算或查看课程级计算结果。

演示重点：

```text
成绩管理回答的是“学生在各考核点上得了多少分，课程目标是否达成”。
```

计算链路可以这样讲：

```text
学生考核点得分 / 考核点满分
-> 得到考核点达成比例
-> 按考核点与课程目标关系汇总
-> 得到课程目标达成度
-> 按课程目标与指标点权重汇总
-> 得到课程级指标点达成度
```

演示注意：

- 如果导入失败，先查看失败行、学号、考核点和错误原因。
- 如果课程级结果为空，检查是否已经导入成绩、配置考核点和课程目标权重。
- 如果页面提示无权限，确认是否使用 `teacher` 或 `edu` 角色。

### 第五步：专业级计算

页面入口：`/calculation`

演示内容：

- 选择专业、学年学期和年级。
- 刷新专业看板，查看课程数和课程级数据准备情况。
- 检查是否可以执行专业级计算。
- 点击执行专业级计算。
- 查看专业级指标点达成度结果。

演示重点：

```text
专业级计算回答的是“一个专业的学生群体是否整体达到毕业要求指标点”。
```

计算链路可以这样讲：

```text
课程级指标点达成度
-> 按矩阵中的课程支撑权重汇总
-> 得到专业级二级指标点达成度
-> 再按毕业要求归类展示
```

演示前置条件：

- 课程库中存在对应专业和学期的课程。
- 课程已经完成课程级计算。
- 矩阵配置中存在课程对指标点的支撑权重。
- 专业、学年学期和年级筛选条件与数据一致。

### 第六步：报表与导出

页面入口：`/report`

演示内容：

- 查看课程报表或专业级报表。
- 展示指标点结果、达成状态和阈值说明。
- 导出 Excel 或 PDF 报表。
- 说明报表用于课程组复核、专业负责人分析和认证材料归档。

演示重点：

```text
报表页面是计算结果的展示和归档出口，方便把平台数据转化为汇报材料。
```

## 4. 一句话讲清 OBE 计算闭环

课堂汇报时可以用下面这句话串起来：

```text
系统先维护专业、课程、学生和指标点等基础数据，再通过矩阵说明课程如何支撑指标点，通过课程大纲说明考核点如何支撑课程目标，最后利用学生成绩计算课程级达成度，并汇总形成专业级毕业要求达成度。
```

## 5. 演示顺序速记

```text
基础数据
-> 毕业要求与指标点
-> 支撑矩阵
-> 课程大纲
-> 成绩导入
-> 课程级计算
-> 专业级计算
-> 报表导出
```

## 6. 汇报时建议强调的改进点

- 登录后按角色进入不同功能，减少无关菜单干扰。
- 基础数据、课程大纲、成绩、计算和报表形成完整 OBE 闭环。
- 已接入后端接口的模块优先使用真实数据，未完成接口的区域保留 Mock 数据用于演示。
- 前端增加了错误提示、导入失败说明、导出命名和文档补充，降低联调和演示成本。
- 后续可以继续完善权限细分、真实数据覆盖率和报表自动生成能力。

## 7. 演示排查清单

| 现象 | 优先检查 |
| --- | --- |
| 看不到菜单 | 当前登录角色是否有权限 |
| 下拉框无数据 | 基础字典、课程库、学年学期是否已维护 |
| 矩阵无法保存 | 权重合计是否满足校验规则 |
| 成绩导入失败 | 模板字段、学生学号、考核点名称是否匹配 |
| 课程级结果为空 | 是否已配置课程目标、考核点并导入成绩 |
| 专业级无法计算 | 课程级结果和矩阵权重是否已准备 |
| 报表无数据 | 是否已经完成对应课程级或专业级计算 |
