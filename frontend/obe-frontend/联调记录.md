# 前后端接口联调记录

更新日期：2026-07-03

本文档记录 OBE 前端与后端接口联调时需要关注的地址、鉴权、角色权限和常见问题。后续如果接口路径、部署地址或账号权限发生变化，应同步更新本文档。

## 1. 当前接口基线

- 前端开发地址：`http://localhost:5173`
- 后端本地地址：`http://localhost:8101/api`
- Swagger 文档地址：`http://localhost:8101/api/doc.html`
- 前端环境变量：`VITE_API_BASE_URL=/api`
- 登录接口：`POST /api/sysuser/login/token`
- 登录态请求头：`Authorization: Bearer <token>`

已接入真实接口页面：

- `dashboard`
- `basic-data`
- `matrix`
- `syllabus`
- `score`
- `calculation`
- `report`

## 2. 前端请求链路

前端页面不要直接拼完整后端地址，统一通过 `src/api` 目录中的接口文件调用。

```text
页面组件
  -> src/api/*.ts
  -> src/api/backend.ts
  -> src/api/request.ts
  -> VITE_API_BASE_URL
  -> Vite 或 Nginx 代理
  -> 后端 /api 接口
```

当前 Axios 基础配置在：

```text
src/api/request.ts
```

关键规则：

- `baseURL` 读取 `VITE_API_BASE_URL`，没有配置时默认 `http://localhost:8101/api`。
- 登录成功后，前端把后端返回的 `token` 存入 `localStorage`。
- 后续请求会自动带上 `Authorization: Bearer <token>`。
- 后端返回业务码 `40100` 时，前端会清理登录态并跳转登录页。

## 3. 本地开发联调流程

1. 启动后端服务，确认后端端口为 `8101`。
2. 打开 Swagger：`http://localhost:8101/api/doc.html`，确认接口文档可访问。
3. 进入前端目录：

   ```bash
   cd frontend/obe-frontend
   ```

4. 安装依赖并启动前端：

   ```bash
   npm install
   npm run dev
   ```

5. 浏览器访问：`http://localhost:5173`。
6. 使用后端数据库中真实存在的账号密码登录。
7. 打开浏览器开发者工具，在 Network 的 Fetch/XHR 中查看接口返回。

## 4. 生产部署联调流程

生产环境建议通过 Nginx 同域代理接口：

```text
浏览器访问 http://服务器IP
  -> 前端静态资源
  -> 请求 /api/xxx
  -> Nginx proxy_pass
  -> 后端 http://127.0.0.1:8101/api/xxx
```

Nginx 代理示例：

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8101/api/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

部署后需要确认：

- 前端页面能访问。
- 后端服务已在服务器上启动。
- Nginx `/api/` 代理地址和后端端口一致。
- 服务器安全组和防火墙允许浏览器访问 `80` 端口。
- 后端能正常连接数据库。

## 7. 常见问题排查

### 502 Bad Gateway

一般说明前端页面访问到了 Nginx，但 Nginx 没有成功转发到后端。

排查顺序：

1. 服务器后端是否启动。
2. 后端端口是否为 `8101`。
3. Nginx `proxy_pass` 是否写成后端真实地址。
4. 后端接口前缀是否为 `/api`。
5. 服务器本机执行 `curl http://127.0.0.1:8101/api/doc.html` 是否能访问。

### timeout of 10000ms exceeded

一般说明请求发出后长时间没有响应。

可能原因：

- 后端服务卡住或未启动。
- 后端数据库连接失败。
- 服务器网络或防火墙阻断。
- 接口查询数据量过大。

### 系统错误 / code 50000

一般说明请求已经到达后端，但后端业务处理失败。

排查顺序：

1. 查看浏览器 Network 中具体失败接口。
2. 在 Swagger 中用同样参数调用该接口。
3. 查看后端控制台异常栈。
4. 检查数据库表和字段是否与后端实体一致。

### 未登录 / code 40100

可能原因：

- token 过期或不存在。
- 前端没有带 `Authorization` 请求头。
- 后端鉴权拦截器未识别当前 token。

处理方式：

- 退出后重新登录。
- 检查 `localStorage.token` 是否存在。
- 在 Network 中确认请求头是否包含 `Authorization: Bearer <token>`。

### 无权限 / 40101 或 403

这通常不是接口没接上，而是当前登录角色没有访问该接口的权限。

处理方式：

- 确认当前页面是否应该由该角色访问。
- 换成对应角色账号重新测试。
- 如果页面必须跨角色调用接口，需要后端调整权限或前端拆分页面能力。

### Swagger 能访问，但前端页面报错

需要重点检查：

- 前端请求路径是否多写或少写 `/api`。
- 请求方法是否一致，例如 `GET` / `POST`。
- 参数位置是否一致，例如 query、body、path variable。
- 是否缺少 token。
- 当前角色是否有权限。

## 8. 当前暂缓优化点

- 根据角色动态隐藏左侧菜单，避免用户点进必然无权限的页面。
- 登录后根据角色默认跳到更合适的首页。
- 对 `40101` 做更明确的前端提示，例如“当前角色无权访问该页面”。
- 对混合权限页面做拆分，避免一个页面里同时依赖多种角色接口。
- `admin` 账号登录异常需要后端确认。
- `matrix/config/{majorId}` 当前测试返回未登录，需要单独复核该接口鉴权或请求方式。
