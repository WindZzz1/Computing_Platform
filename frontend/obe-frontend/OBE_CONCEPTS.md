# OBE 核心概念说明

本文档用于说明前端页面中常见的 OBE 业务概念，帮助开发、联调和课堂演示时统一说法。

## 1. 核心概念

### 毕业要求

毕业要求是专业认证中对学生毕业时应具备能力的总体描述。例如工程知识、问题分析、设计开发解决方案等。它是专业层面的培养目标拆解结果。

前端对应位置：

- 基础数据管理
- 毕业要求管理
- 报表中心

### 指标点

指标点是毕业要求的进一步拆分。一个毕业要求通常会拆成多个可评价的指标点，例如 `1.1`、`1.2`、`2.1`。指标点比毕业要求更具体，后续课程、成绩和达成度计算都会围绕指标点展开。

前端对应位置：

- 基础数据管理
- 指标点管理
- 矩阵配置
- 专业级计算
- 报表中心

### 课程目标

课程目标是某一门课程希望学生通过学习达到的能力目标。例如“掌握基本数据结构”“能够分析算法复杂度”等。课程目标属于课程内部目标，但需要支撑专业层面的指标点。

前端对应位置：

- 课程大纲管理
- 课程目标与权重

### 考核点

考核点是课程中实际产生分数的评价项，例如平时作业、实验报告、期末考试、课程设计等。考核点成绩先用于计算课程目标达成度，再进一步支撑指标点达成度。

前端对应位置：

- 课程大纲管理
- 考核点管理
- 成绩导入与预览

## 2. 概念之间的关系

可以把 OBE 计算链路理解为从“学生成绩”逐级汇总到“专业毕业要求”的过程：

```text
考核点成绩
  -> 课程目标达成度
  -> 指标点课程级达成度
  -> 指标点专业级达成度
  -> 毕业要求达成情况
```

更具体地说：

1. 教师在课程大纲中维护课程目标和考核点。
2. 教师配置考核点对课程目标的内部贡献权重。
3. 专业负责人或管理员配置课程目标对指标点的支撑关系。
4. 教务或教师导入学生成绩。
5. 系统根据成绩和权重计算课程级达成度。
6. 专业级计算读取多门课程的课程级结果，汇总得到专业指标点达成度。

## 3. 权重关系

### 内部贡献权重

内部贡献权重表示同一门课程内部，不同课程目标对某个指标点的贡献比例。页面中通常会校验同一指标点下的权重合计是否为 `1.00`。

示例：

```text
指标点 1.1 = CO1 * 0.60 + CO2 * 0.40
```

### 支撑矩阵权重

支撑矩阵描述课程对毕业要求指标点的支撑关系。它用于说明某门课程是否支撑某个指标点，以及支撑强度是多少。

示例：

```text
数据结构课程 -> 指标点 1.1，权重 0.30
操作系统课程 -> 指标点 1.1，权重 0.25
```

## 4. 课程级达成度

课程级达成度关注“一门课内部”的达成情况。

它通常由以下数据共同决定：

- 学生在各考核点上的成绩
- 考核点满分
- 考核点与课程目标的对应关系
- 课程目标与指标点的权重关系

前端页面中的作用：

- 成绩导入后，可以查看课程内学生成绩。
- 执行课程级计算后，可以得到该课程对相关指标点的达成度。
- 课程级结果是专业级计算的前置数据。

## 5. 专业级达成度

专业级达成度关注“整个专业”的培养目标是否达成。

它会读取多门课程已经计算完成的课程级结果，再按照专业培养方案、课程支撑矩阵和指标点权重进行汇总，得到某个年级、某个学期或某个专业范围下的指标点达成情况。

前端页面中的作用：

- 查看专业看板，确认课程级结果是否齐全。
- 执行专业级计算，汇总多个课程的达成度结果。
- 对照阈值判断指标点是否达标。
- 为报表导出提供结果数据。

## 6. 演示时的推荐讲法

可以按下面顺序介绍：

1. 先说明基础数据：学院、专业、课程、学生、学年学期是系统运行的基础。
2. 再说明认证目标：毕业要求被拆成指标点，指标点是后续计算的评价对象。
3. 然后说明课程侧配置：课程目标和考核点描述一门课如何评价学生。
4. 接着说明映射关系：课程目标通过权重支撑指标点。
5. 最后说明计算链路：学生成绩先算课程级，再汇总到专业级，最终形成报表。

一句话总结：

```text
前端围绕“基础数据维护 -> 大纲与矩阵配置 -> 成绩导入 -> 课程级计算 -> 专业级计算 -> 报表输出”组织页面，把学生成绩逐级转换为专业认证需要的达成度结果。
```
